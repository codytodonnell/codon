## Overview

In association with Syracuse University Libraries, the goal for this summer-long project was to discover ways to spatially represent and visualize elements of the Marcel Breuer Digital Archive (MBDA).  To begin doing this, we divided research into two initial subgroups: geospatial mapping and social network mapping.  I was tasked with researching and developing ways to visualize the network of constituents involved in the projects from the MBDA.  The goal here was to build a visual network that would point out the key players in Marcel Breuer’s long and impactful career in the architecture field.

## Palladio Prototyping

We initially explored the online data analytics tool, Palladio as a way to do both geospatial and network visualization.  Palladio is an extremely powerful tool, allowing you to simply upload any type of data file (Excel spreadsheets in our case) and have a data model generate automatically within seconds.  After uploading data, you can quickly begin to build network graphs of your data points, specifying which attributes from the data you would like to associate.  I used Palladio to create some initial graphs with small amounts of our scope data, specifying “People” and “Projects” as the target attributes. But, it became apparent that there was a lack of customization, control, and scalability in Palladio’s software.  Testing with more than 1,000 records of our scope data would crash the site and even when large amounts of data would render a graph, it would be too crowded and unreadable.

## D3 Prototyping

After concluding that Palladio would not accomplish what we were hoping to see in a network visualization, we began discussing the use of D3.js as a more scalable and customizable alternative.  I researched a few examples of network graphs that utilize D3 and narrowed our options down to Force-Directed Graphs and Hierarchical Edge Bundling Graphs (HEB).  We ultimately decided on the HEB graph for two main reasons: (1) the wheel shape could handle a lot of data while maintaining a consistent shape and size, and (2) the way our data is formatted lends itself well to the HEB standards.  I began experimenting with HEB graphs, starting with small amounts of data and eventually inputting two projects from the scope.  Initially I used the Excel files in conjunction with Palladio to format the data in compatibility with the HEB graph.  Shortly after this initial testing period, we received access to a dump of the current version of the MBDA.  Access to the database allowed me to figure out how the right data can be extracted to create the types of files needed to build an HEB graph.  Figuring this out allowed me to add the rest of the scope data to the HEB graph and it also allowed me to define an iterative process for adding more data to the graph in the future.

## Feature Development

After reformatting the old data and formatting the new data, my main tasks became adding features to the HEB graph so that it looked and functioned the way we wanted.  The most difficult feature to complete was the node-filtering feature but after troubleshooting, researching, and finding the right resources I was able to create a fluid filtering system.  Among other features and elements are node-highlighting, which displays only the links connected to the target node, node-sizing, which correlates name-size to the amount of objects the target person is related to, tooltip, which displays person name, number of objects, and roles when target person is rolled over, revert after rollover, which allows the user to choose whether the graph snaps back to full or remains on the target links after a rollover, and finally graph rotation, allowing users to click and drag inside the graph to rotate the whole visualization.
